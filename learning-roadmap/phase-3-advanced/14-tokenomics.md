## 1. JACK 발행 경제학

### 1.1 기본 구조

```
블록 보상: 50 JACK (고정)
블록 타임: 30초
반감기: 없음 (영원히 50 JACK)

시간당 발행:
  3600초 ÷ 30초 = 120 블록/시간
  120 × 50 = 6,000 JACK/시간

일일 발행:
  6,000 × 24 = 144,000 JACK/일

주간 발행:
  144,000 × 7 = 1,008,000 JACK/주

6주(SSAFY) 발행:
  144,000 × 42 = 6,048,000 JACK (~600만)
```

### 1.2 발행량 추이

```
시간       │ 총 발행량        │ 비고
───────────┼─────────────────┼──────────
1시간      │ 6,000 JACK      │ 시작
1일        │ 144,000         │
1주        │ 1,008,000       │ ~100만
3주        │ 3,024,000       │ ~300만
6주(MVP끝) │ 6,048,000       │ ~600만
1년        │ 52,560,000      │ ~5300만
```

### 1.3 인플레이션율

```
인플레이션 = 신규 발행 ÷ 기존 총량

특징: 총량이 늘수록 인플레이션율은 감소

  1일차: ∞ (0 → 144,000)
  1주차: 144,000 ÷ 1,008,000 = 14.3%/일
  6주차: 144,000 ÷ 6,048,000 = 2.4%/일
  1년:   144,000 ÷ 52,560,000 = 0.27%/일

연간 인플레이션:
  1년차: 52,560,000 ÷ 26,280,000(반년 평균) ≈ 200%
  2년차: 52,560,000 ÷ 78,840,000(1.5년 평균) ≈ 67%
  5년차: 약 20%
  10년차: 약 10%

→ 초기에는 인플레이션 높지만 점점 감소
→ 그래도 0%에 수렴하지는 않음 (Bitcoin과 다른 점)
```

### 1.4 Bitcoin과 비교

```
┌───────────────┬──────────────────┬──────────────────┐
│               │ Bitcoin          │ JackpotChain     │
├───────────────┼──────────────────┼──────────────────┤
│ 블록 보상     │ 50→25→12.5→...  │ 50 (고정)        │
│ 반감기        │ 210,000 블록     │ 없음             │
│ 총 발행량     │ 2100만 BTC (한정) │ 무제한           │
│ 블록 타임     │ 10분             │ 30초             │
│ 장기 인플레   │ 0% (수렴)       │ ~10%/년 (감소)   │
│ 채굴 인센티브 │ 수수료 의존      │ 보상 영구 지속   │
└───────────────┴──────────────────┴──────────────────┘

JackpotChain이 무제한 발행을 선택한 이유:

  1. 채굴 인센티브 영구 보장
     Bitcoin: 보상이 0에 수렴 → 수수료만으로 채굴?
     JackpotChain: 50 JACK 영원히 → 채굴 동기 유지

  2. 가챠 경제 유지
     잭팟 풀에 수수료가 계속 흘러야 함
     → TX가 계속 발생해야 함
     → 채굴 인센티브가 있어야 네트워크 유지

  3. MVP 단순성
     반감기 로직 불필요
     → 구현 간단, 경제 예측 쉬움

  4. 소각이 인플레이션을 상쇄
     발행만 있는 게 아님
     → 수수료 20% 소각 + Exchange 소각
     → 실질 인플레이션은 더 낮음
```

## 2. 수수료 분배

### 2.1 분배 구조

```
TX 수수료 발생
     │
     ├─── 50% ──→ 채굴자 (블록 보상에 합산)
     │
     ├─── 30% ──→ 잭팟 풀 (시스템 주소 축적)
     │
     └─── 20% ──→ 소각 (OP_RETURN, 영구 소멸)

블록 보상 50 JACK → 100% 채굴자 (수수료와 무관)
```

### 2.2 각 분배처의 경제학적 역할

```
=== 채굴자 50% ===

역할: 네트워크 보안 인센티브
  → 해시파워 투입 동기
  → 채굴자가 많을수록 51% 공격 어려워짐

왜 50%?
  너무 낮으면: 채굴 이탈 → 보안 약화
  너무 높으면: 잭팟 풀 축적 느림 → 가챠 매력 감소
  50%: 보안과 가챠 밸런스


=== 잭팟 풀 30% ===

역할: 가챠 당첨금 재원
  → TX가 활발할수록 풀이 빨리 참
  → 풀이 클수록 가챠 매력 증가
  → 가챠 매력 → POT 수요 → Exchange 활성화
  → Exchange → 수수료 발생 → 선순환!

왜 30%?
  너무 낮으면: 풀 축적 느림 → 당첨금 작음 → 매력 없음
  너무 높으면: 채굴자 몫 감소 → 보안 약화
  30%: 적절한 축적 속도


=== 소각 20% ===

역할: 인플레이션 억제
  → 무제한 발행의 균형추
  → 유통량 증가 속도를 늦춤
  → 장기적 가치 안정

왜 20%?
  너무 낮으면: 인플레이션 심화
  너무 높으면: 유통량 부족 → 경제 위축
  20%: 발행과 소각의 균형점
```

### 2.3 수수료 시뮬레이션

```
=== 가정 ===
블록당 평균 TX: 100개
TX당 평균 수수료: 0.01 JACK
블록당 수수료 총합: 1 JACK

=== 블록당 분배 ===
채굴자: 50 JACK(보상) + 0.5 JACK(수수료) = 50.5 JACK
잭팟:   0.3 JACK
소각:   0.2 JACK

=== 일일 (120블록/시간 × 24시간 = 2880블록) ===
채굴자 총수입: 50.5 × 2880 = 145,440 JACK/일
잭팟 유입:     0.3 × 2880 = 864 JACK/일
소각:          0.2 × 2880 = 576 JACK/일

=== 주간 ===
잭팟 유입: 864 × 7 = 6,048 JACK/주
소각:      576 × 7 = 4,032 JACK/주

=== 6주 (MVP) ===
잭팟 축적: 6,048 × 6 = 36,288 JACK (당첨 없을 때)
총 소각:   4,032 × 6 = 24,192 JACK

순 발행 (발행 - 소각):
  6,048,000 - 24,192 = 6,023,808 JACK
  → 소각 비율: 0.4% (초기에는 미미)
```

### 2.4 수수료가 높아지면?

```
=== TX 활발 시나리오 ===
블록당 TX: 500개
TX당 수수료: 0.05 JACK
블록당 수수료: 25 JACK

채굴자: 50 + 12.5 = 62.5 JACK/블록
잭팟:   7.5 JACK/블록
소각:   5 JACK/블록

일일 잭팟 유입: 7.5 × 2880 = 21,600 JACK
일일 소각:      5 × 2880 = 14,400 JACK

→ TX 활발하면 잭팟도, 소각도 빨라짐
→ 경제가 활성화될수록 시스템이 잘 돌아감
```

## 3. 잭팟 풀 시뮬레이션

### 3.1 축적 모델

```
풀 잔액 변화:
  유입: 매 블록 수수료의 30%
  유출: 가챠 당첨 시 풀의 50~80% 지급

잔액(t+1) = 잔액(t) + 유입 - 유출

유입은 예측 가능 (TX 활동에 비례)
유출은 확률적 (가챠 당첨 시에만)
```

### 3.2 시뮬레이션: 당첨 없을 때

```
가정: 블록당 잭팟 유입 0.3 JACK, 당첨 없음

Block  │ 풀 잔액
───────┼──────────
0      │ 0 JACK
1000   │ 300 JACK
5000   │ 1,500 JACK
10000  │ 3,000 JACK
50000  │ 15,000 JACK
(6주)  │ ~72,576 JACK

→ 선형 증가 (일정 속도로 쌓임)
→ 당첨이 없으면 계속 커짐
```

### 3.3 시뮬레이션: 당첨 발생

```
가정: 
  블록당 유입 0.3 JACK
  당첨 확률 1% (가챠 플레이당)
  당첨금 비율 60%

시나리오:

Block 0~5000: 축적
  풀: 0 → 1,500 JACK

Block 5001: 당첨 발생!
  당첨금: 1,500 × 60% = 900 JACK
  풀 잔액: 1,500 - 900 = 600 JACK

Block 5002~10000: 다시 축적
  풀: 600 → 600 + 1,500 = 2,100 JACK

Block 10001: 또 당첨!
  당첨금: 2,100 × 60% = 1,260 JACK
  풀 잔액: 2,100 - 1,260 = 840 JACK

패턴:
  쌓이고 → 당첨으로 줄고 → 다시 쌓이고
  풀이 0이 되지는 않음 (60%만 지급하니까)
  시간이 지날수록 기저 잔액이 조금씩 증가
```

### 3.4 당첨금 비율에 따른 풀 변화

```
풀 잔액 1000 JACK, 당첨 발생 시:

비율 50%: 당첨금 500, 잔여 500 (안정적)
비율 60%: 당첨금 600, 잔여 400 (균형)
비율 70%: 당첨금 700, 잔여 300 (공격적)
비율 80%: 당첨금 800, 잔여 200 (위험)

비율이 높을수록:
  ✅ 당첨금 커짐 → 가챠 매력 증가
  ❌ 풀 회복 느림 → 다음 당첨금 작음
  
비율이 낮을수록:
  ✅ 풀 안정적 → 꾸준한 당첨금
  ❌ 당첨금 작음 → 가챠 매력 감소

MVP 권장: 60% (밸런스)
→ 추후 운영하면서 조정
```

### 3.5 풀 고갈 시나리오

```
걱정: 당첨이 연속으로 나오면 풀이 바닥?

Block 1000: 풀 1000 JACK, 당첨! → 600 지급, 잔여 400
Block 1003: 풀 401 JACK, 또 당첨! → 240 지급, 잔여 161
Block 1005: 풀 162 JACK, 또 당첨! → 97 지급, 잔여 65

관찰:
  풀은 줄어들지만 0이 되지 않음
  → 항상 (100% - 당첨비율)만큼 남음
  → 60% 비율이면 매번 40% 잔류
  → 수학적으로: 잔액 × 0.4^n (n=연속 당첨 횟수)
  
  3연속 당첨: 1000 × 0.4³ = 64 JACK (아직 있음)
  5연속 당첨: 1000 × 0.4⁵ = 10 JACK (거의 바닥)
  
  하지만:
  → 그 사이에도 수수료 유입은 계속됨
  → 당첨 확률이 1%면 5연속은 0.01⁵ = 0.00000001%
  → 사실상 불가능
```

### 3.6 풀이 과대해지는 시나리오

```
걱정: 아무도 가챠를 안 하면 풀만 계속 쌓임?

6주 동안 당첨 0건:
  풀 잔액: ~72,576 JACK
  총 발행: ~6,048,000 JACK
  풀 비율: 0.6% (전체 발행량 대비)
  
  → 문제 없음 (전체 대비 미미)

1년 동안 당첨 0건:
  풀 잔액: ~630,000 JACK
  총 발행: ~105,120,000 JACK
  풀 비율: 0.6%
  
  → 여전히 문제 없음
  → 아무도 가챠를 안 하면 풀만 커질 뿐
  → 큰 당첨금이 유저를 끌어들이는 효과

결론: 풀 과대는 오히려 좋은 것 (가챠 매력 증가)
```

## 4. 소각 분석

### 4.1 소각 경로

```
JackpotChain에서 JACK이 소각되는 2가지 경로:

경로 1: 수수료 소각 (20%)
  매 블록 Coinbase TX에서 수수료의 20%
  → OP_RETURN으로 영구 소멸
  → 자동, 예측 가능

경로 2: Exchange 소각
  JACK → POT 교환 시 JACK 전액 소각
  → 교환 비율만큼 POT 생성
  → 유저 행동에 의존, 가변적
```

### 4.2 발행 vs 소각 균형

```
=== 시나리오 A: 수수료 소각만 (Exchange 없을 때) ===

일일 발행: 144,000 JACK (블록 보상)
일일 수수료 소각: 576 JACK (블록당 0.2 × 2880)

순 발행: 144,000 - 576 = 143,424 JACK/일
소각 비율: 0.4%

→ 소각이 발행을 상쇄하기엔 턱없이 부족
→ 수수료 소각만으로는 인플레이션 억제 미미


=== 시나리오 B: Exchange 활발 ===

일일 Exchange: 유저 100명 × 1000 JACK = 100,000 JACK 소각

일일 발행: 144,000 JACK
일일 소각: 576 + 100,000 = 100,576 JACK

순 발행: 144,000 - 100,576 = 43,424 JACK/일
소각 비율: 70%

→ Exchange가 활발하면 소각 효과 큼!


=== 시나리오 C: 균형점 ===

순 발행 = 0이 되려면?
  필요 소각 = 144,000 JACK/일
  수수료 소각: ~1,152 JACK/일
  Exchange 소각 필요: 286,848 JACK/일
  
  → 매일 286,848 JACK이 POT으로 교환되어야 균형
  → 현실적으로 어려움 (유저가 엄청 많아야)
  
결론:
  JackpotChain은 기본적으로 인플레이션 체인
  소각은 인플레이션을 "줄이는" 역할
  0%로 만드는 것이 목표가 아님
```

### 4.3 소각의 진짜 가치

```
소각이 인플레이션을 완전히 상쇄 못 해도:

  1. 심리적 효과
     "20%가 소각된다" → 희소성 인식
     → 단순한 무제한 발행보다 신뢰감

  2. Exchange 소각의 선순환
     JACK 소각 → POT 생성 → 가챠 → 잭팟 풀에서 JACK 지급
     → JACK이 "순환"하면서 경제 활성화

  3. TX 활동 연동
     TX 많을수록 소각 많음
     → 네트워크 활발 = 소각 활발 = 인플레이션 억제
     → 자연스러운 균형 메커니즘
```

## 5. JACK ↔ POT 교환 경제학

### 5.1 교환 비율

```
v1 (MVP): 고정 비율
  100 JACK = 1 POT

의미:
  POT 1개 = 가챠 1회
  가챠 1회 비용 = 100 JACK

  블록 보상이 50 JACK이니까:
    채굴 2블록 = 가챠 1회 분량
    → 약 30초 채굴 = 가챠 1회
```

### 5.2 교환이 경제에 미치는 영향

```
Exchange TX가 발생하면:

  1. JACK 유통량 감소
     1000 JACK → 소각됨
     → 디플레이션 압력

  2. POT 유통량 증가
     10 POT 새로 생성
     → POT 경제 활성화

  3. 수수료 발생
     Exchange TX에도 수수료 있음
     → 수수료 분배 (채굴자/잭팟/소각)

  4. 잭팟 풀 간접 기여
     Exchange → 가챠 → 경제 활동 → 수수료 → 잭팟 유입
```

### 5.3 POT의 운명

```
POT의 생애주기:

  탄생: Exchange TX (JACK 소각 대가)
     ↓
  보유: 유저 지갑 (전송 가능)
     ↓
  소비: Gacha Commit TX
     ↓
  소멸: 소각 (POT 영구 제거)

POT은 순환하지 않음:
  생성 → 사용 → 소멸 (일방향)
  → 지속적으로 Exchange가 필요
  → JACK이 계속 소각되는 구조
```

### 5.4 v2 (미래): AMM 방식

```
MVP 이후 고려사항:

고정 비율의 문제:
  100 JACK = 1 POT이 항상 적절한가?
  JACK 가치가 변하면? 가챠 비용이 너무 싸거나 비싸질 수 있음

AMM (Automated Market Maker):
  유동성 풀에 JACK과 POT을 넣어두고
  수요/공급에 따라 비율이 자동 조정
  
  JACK 수요 높음 → POT이 더 비싸짐
  POT 수요 높음 → JACK이 더 비싸짐

  → Phase 3 이후 고려 (MVP에서는 고정 비율)
```

## 7. 합의 규칙 변경

### 7.1 변경 가능한 파라미터

```
경제 파라미터:
  ✏️ 블록 보상 (50 JACK)
  ✏️ 수수료 분배 비율 (50/30/20)
  ✏️ 교환 비율 (100:1)
  ✏️ 가챠 비용 (1 POT)
  ✏️ 당첨금 비율 (60%)
  ✏️ 당첨 확률 (1%)
  ✏️ Reveal 기한 (50블록)

프로토콜 파라미터:
  ✏️ 블록 타임 (30초)
  ✏️ 블록 크기 (1 MB)
  ✏️ 난이도 조절 주기 (50블록)
  ✏️ 최소 수수료 (0.001 JACK/byte)
  ✏️ 최소 JACK (0.01 JACK)
```

### 7.2 변경 방법 3가지

```
=== 1. 하드포크 (Hard Fork) ===

정의: 이전 버전과 호환 안 되는 규칙 변경

예: 수수료 분배 50/30/20 → 40/40/20

  구버전 노드: "채굴자 50% 아니네? 무효!" ❌
  신버전 노드: "40%가 맞아, 유효!" ✅
  → 동시 업데이트 필수, 아니면 체인 분열

적용:
  규칙을 느슨하게 만들 때
  기존 규칙과 다른 방향의 변경


=== 2. 소프트포크 (Soft Fork) ===

정의: 이전 버전과 호환되는 규칙 변경 (더 엄격해지는 방향만)

예: 최소 수수료 0.001 → 0.01 JACK/byte (더 비싸게)

  구버전 노드: "0.01이면 0.001 이상이니까 유효!" ✅
  신버전 노드: "0.01이면 0.01 이상이니까 유효!" ✅
  → 구버전도 새 블록을 수락

적용:
  규칙을 더 엄격하게 만들 때만
  기능 추가 (기존 무시하던 데이터에 의미 부여)

제한:
  수수료 비율 변경 같은 건 소프트포크로 어려움


=== 3. 활성화 높이 (Activation Height) ===

정의: 코드에 미리 "높이 X부터 새 규칙 적용"을 넣어두기

예:
  BLOCK_HEIGHT < 10000 → Phase 1 규칙
  BLOCK_HEIGHT ≥ 10000 → Phase 2 규칙

  모든 노드가 같은 코드 실행
  → 높이 10000에 자동 전환
  → 분열 없음

적용:
  사전 계획된 변경
  모든 노드가 같은 버전일 때

JackpotChain MVP에 가장 적합!
```

### 7.3 MVP에서의 현실

```
MVP 환경:
  노드 6개, 전부 우리 팀 소유

변경이 필요한 상황:
  "잭팟이 너무 안 쌓여" → 비율 조정
  "수수료가 너무 비싸" → 최소 수수료 조정
  "가챠가 재미없어" → 확률/비용 조정

변경 방법:
  1. 팀 회의: "비율 바꾸자"
  2. 코드 수정: 활성화 높이 추가
  3. 빌드 & 배포: 6개 노드 동시 업데이트
  4. 활성화 높이 도달: 자동 전환
  → 끝! (10분이면 됨)

주의:
  활성화 높이 이전 블록은 이전 규칙으로 검증
  → 과거 체인 무결성 유지
  → IBD 때도 올바르게 검증됨
```

### 7.4 코드 구조 예시

```
경제 파라미터를 한 곳에 모아두기:

=== 파라미터 설정 ===

Phase 1 (Block 0 ~ 9999):
  BLOCK_REWARD = 50 JACK
  FEE_MINER_RATIO = 50%
  FEE_JACKPOT_RATIO = 30%
  FEE_BURN_RATIO = 20%
  EXCHANGE_RATE = 100  (100 JACK = 1 POT)
  GACHA_COST = 1 POT
  JACKPOT_PAYOUT_RATIO = 60%
  REVEAL_DEADLINE = 50 blocks

Phase 2 (Block 10000~):
  FEE_MINER_RATIO = 40%     ← 변경!
  FEE_JACKPOT_RATIO = 40%   ← 변경!
  (나머지 동일)

→ 블록 높이에 따라 자동 전환
→ 과거 블록 검증에도 올바른 규칙 적용
```

### 8.2 튜닝 가이드

```
"인플레이션이 심해"
  → 소각 비율 20% → 30%
  → 또는 블록 보상 50 → 30 JACK

"당첨금이 너무 작아"
  → 당첨금 비율 60% → 80%
  → 또는 잭팟 비율 30% → 40%

핵심: 하나를 바꾸면 다른 곳에 영향
  → 한 번에 하나만 바꾸고 관찰!
```

```
채굴자 50%: 네트워크 보안
```

```
풀이 0이 되지 않음 (항상 잔류분 존재)
TX 활발할수록 빠르게 쌓임
```

```
수수료 20% + Exchange JACK 전액
인플레이션 완전 상쇄는 어려움
경제 활성화와 연동되는 자연 균형
```
