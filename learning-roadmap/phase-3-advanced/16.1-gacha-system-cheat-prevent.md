## 1. V3의 한계 재검토

### 1.1 블록 폐기 공격 복습

```
V3에서 남은 공격:
  채굴자가 자기 Commit TX를 포함한 블록 채굴
  → 당첨 여부 계산
  → 꽝이면 블록 폐기, 다시 채굴
  → 당첨 나올 때까지 반복

경제적 억제:
  블록 폐기 = 50 JACK 블록 보상 포기
  → 조작 비용 발생

문제:
  해시파워가 높은 채굴자일수록 공격 용이
  → 독점 채굴 환경에서 억제력 약화
```

### 1.2 해시파워와 공격 실효성

```
채굴자 A의 해시파워 비율에 따른 공격 비용:

  해시파워 10%:
    블록 폐기 → 90% 확률로 다른 채굴자가 먼저 채굴
    → Commit 자체가 무효화될 위험 높음
    → 공격 비용 매우 높음

  해시파워 50%:
    블록 폐기 → 50% 확률로 다시 본인이 채굴
    → 공격 비용 중간

  해시파워 90%:
    블록 폐기 → 90% 확률로 다시 본인이 채굴
    → 공격 비용 낮음 ⚠️
```

## 2. 블록타임 단축의 억제 효과

### 2.1 핵심 통찰

```
짧은 블록타임 = 공격의 기회비용 증가

이유:
  1. 블록 폐기 → 다른 채굴자가 빠르게 채굴
  2. Commit TX가 다른 블록에 포함됨
  3. 본인 block_hash로 계산 불가
  4. 채굴보상도 잃음

결론:
  "꽝이어도 50 JACK이라도 챙기자" 심리 유도
```

### 2.2 시나리오 분석

```
=== 긴 블록타임 (10분, Bitcoin 수준) ===

Block 100: A가 Commit
Block 101: A가 채굴 (10분 후)
  → 꽝
  → A: "폐기하고 다시 채굴해도 10분 여유 있음"
  → 폐기 후 재시도 가능
  → 공격 가능!


=== 짧은 블록타임 (30초, JackpotChain) ===

Block 100: A가 Commit
Block 101: A가 채굴 (30초 후)
  → 꽝
  → A: "폐기하면 30초 내에 B가 채굴할 수 있음"

  [선택지]
  ├─ 폐기 → B가 101 채굴 (높은 확률)
  │        → A의 Commit은 B의 block_hash 기준
  │        → A는 50 JACK 날림
  │        → 결과도 다시 계산해야 함 (당첨 보장 없음)
  │
  └─ 공개 → 꽝이지만 50 JACK 확보
           → 안전한 선택

→ 합리적 선택: 공개!
```

### 2.3 게임이론 손익 분석

```
파라미터:
  - 블록 보상: 50 JACK
  - 잭팟 풀: 1,000 JACK
  - 당첨금: 600 JACK (60%)
  - 당첨 확률: 1%
  - A의 해시파워: 50%
  - 블록타임: 30초

폐기 시 기대값:
  B가 먼저 채굴할 확률: 50%

  Case 1: A가 다시 채굴 (50%)
    → 다시 1% 당첨 도전
    → 기대값: 0.01 × 600 = 6 JACK

  Case 2: B가 먼저 채굴 (50%)
    → A의 block_hash가 아님
    → Commit은 B의 블록에 대해 계산됨
    → A는 새로운 Commit 필요 (1 POT 추가 비용)
    → 채굴보상 50 JACK 손실
    → 기대값: -50 JACK

  총 기대값: 0.5 × 6 + 0.5 × (-50) = 3 - 25 = -22 JACK

공개 시 기대값:
  → 50 JACK 확보 (블록보상)
  → 기대값: 50 JACK

결론:
  폐기 기대값 (-22) << 공개 기대값 (50)
  → 합리적 채굴자는 폐기 안 함!
```

### 2.4 블록타임별 억제력 비교

| 블록타임 | B가 먼저 채굴 확률 | 폐기 손실 기대값 | 억제력 |
|----------|-------------------|------------------|--------|
| 10분 | ~5% | -2.5 JACK | 약함 |
| 1분 | ~30% | -15 JACK | 중간 |
| 10초 | ~50% | -25 JACK | **강함** |
| 5초 | ~60% | -30 JACK | 매우 강함 |

```
결론:
  JackpotChain의 30초 블록타임은
  V3 경제적 억제를 크게 강화함!
```

## 3. 복합 억제 메커니즘

### 3.1 현재 구현된 억제 (V3+)

```
┌──────────────────────────────────────────────────────────────┐
│                    V3+ 억제 메커니즘                          │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  Layer 1: Commit-Reveal 분리                                 │
│    → 유저는 block_hash 모름                                  │
│    → 채굴자는 secret 모름                                    │
│    → 단독 조작 원천 차단                                     │
│                                                              │
│  Layer 2: 블록 보상 포기 비용                                │
│    → 블록 폐기 = 50 JACK 손실                                │
│    → 기본적인 경제적 억제                                    │
│                                                              │
│  Layer 3: 짧은 블록타임 (30초)                               │
│    → 폐기 시 다른 채굴자가 먼저 채굴할 확률 ↑                │
│    → 기회비용 극대화                                         │
│    → "차라리 꽝이어도 보상 챙기자" 유도                      │
│                                                              │
│  Layer 4: 최소 2블록 간격                                    │
│    → Commit과 Reveal 분리                                    │
│    → Commit 블록 채굴자 ≠ Reveal 블록 채굴자 (대부분)        │
│                                                              │
│  Layer 5: 당첨금 Commit 시점 고정                            │
│    → 지연 치트 방지                                          │
│    → 풀 성장 기다림 무의미                                   │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 공격 성공 조건

```
채굴자가 블록 폐기 공격으로 이득을 보려면:

  1. 해시파워 > 50% (폐기해도 다시 채굴 가능)
  2. 잭팟 풀 충분히 큼 (당첨금 > 폐기 비용)
  3. 경쟁 채굴자 없음 (폐기해도 다른 채굴자 없음)

JackpotChain MVP 환경:
  - 6노드 운영 = 해시파워 분산 (~17% 각)
  - 잭팟 풀 소규모
  - 팀원 = 신뢰 기반

→ 공격 조건 충족 어려움!
```

## 4. 미래 개선 방향

### 4.1 Uncle Block 보상 (고려 중)

```
문제:
  짧은 블록타임 → 고아 블록(Orphan) 증가
  → 채굴자 보상 불안정
  → 채굴자 이탈 가능성

해결책: Uncle 보상 (Ethereum 방식)

  Main Chain:  [100] ← [101] ← [102]
                  ↖
  Uncle:          [101'] ← 고아됨

  Uncle 보상:
    - 정상 블록: 100%
    - Uncle 블록: 87.5% ~ 25% (거리에 따라)

효과:
  1. 고아 블록에도 보상 → 채굴자 UX 개선
  2. 전체 해시파워 인정 → 보안 강화
  3. 짧은 블록타임의 부작용 완화
```

### 4.2 Uncle 보상 공식

```
uncle_reward = base_reward × (8 - distance) / 8

거리 | 보상 비율
-----|----------
  1  | 87.5% (7/8)
  2  | 75.0% (6/8)
  3  | 62.5% (5/8)
  4  | 50.0% (4/8)
  5  | 37.5% (3/8)
  6  | 25.0% (2/8)
  7+ | 0%

예시:
  블록 보상: 50 JACK
  Uncle (거리 1): 50 × 7/8 = 43.75 JACK
  → 완전 손실 아님!
```

### 4.3 다른 체인 사례

| 체인 | 블록타임 | 고아 보상 | 비고 |
|------|----------|:---------:|------|
| Bitcoin | 10분 | ❌ | 고아 발생 희소 |
| Ethereum (PoW) | 15초 | ✅ | Uncle 87.5%~25% |
| Ethereum Classic | 15초 | ✅ | 동일 |
| Conflux | 1초 | ✅ | GHOST 프로토콜 |
| **JackpotChain** | 30초 | ❌ (향후 ✅) | 검토 중 |

### 4.4 구현 우선순위

```
Phase 1 (현재 - MVP):
  ✅ V3 경제적 억제
  ✅ 짧은 블록타임 (30초)
  ✅ 최소 2블록 간격
  → MVP에 충분

Phase 2 (향후):
  ⬜ Uncle Block 보상
  ⬜ 고아 블록 통계 모니터링
  → 메인넷 전 검토

Phase 3 (장기):
  ⬜ 다중 블록 해시 혼합
  ⬜ VRF (검증 가능 랜덤)
  → 대규모 운영 시 고려
```

## 5. 종합 보안 분석

### 5.1 공격 벡터별 방어 상태 (업데이트)

```
┌──────────────────────────┬───────┬─────────────────────────────┐
│ 공격                     │ 방어  │ 방어 수단                   │
├──────────────────────────┼───────┼─────────────────────────────┤
│ 유저: secret 미리 계산   │ ✅    │ block_hash 혼합             │
├──────────────────────────┼───────┼─────────────────────────────┤
│ 채굴자: hash 단독 조작   │ ✅    │ secret 비공개               │
├──────────────────────────┼───────┼─────────────────────────────┤
│ 채굴자: 블록 폐기        │ ✅⚠️  │ 블록보상 손실               │
│                          │       │ + 짧은 블록타임 (기회비용)  │
│                          │       │ + 다른 채굴자 경쟁          │
├──────────────────────────┼───────┼─────────────────────────────┤
│ 지연 치트                │ ✅    │ Commit 시점 풀 잔액 고정    │
├──────────────────────────┼───────┼─────────────────────────────┤
│ 프론트러닝               │ ✅    │ 서명 필수                   │
├──────────────────────────┼───────┼─────────────────────────────┤
│ Commit-Reveal 동일블록   │ ✅    │ 최소 2블록 간격             │
└──────────────────────────┴───────┴─────────────────────────────┘

✅ = 구조적/경제적으로 방어됨
⚠️ = 극단적 환경(90%+ 해시파워)에서 이론적 가능
```

### 5.2 JackpotChain V3+의 강점

```
1. 다층 방어 (Defense in Depth)
   → 하나의 억제 실패해도 다른 억제 작동

2. 경제적 합리성 기반
   → "불가능"이 아닌 "비합리적"으로 설계
   → 합리적 행위자 가정 시 안전

3. 투명성
   → 모든 가챠 기록 온체인
   → 비정상 패턴 즉시 감지 가능
   → 사후 감사 가능

4. MVP 환경 최적화
   → 6노드 팀원 운영
   → 신뢰 기반 + 기술적 억제 결합
```

## 6. 요약

### 핵심 개선점

```
기존 V3:
  블록 폐기 = 50 JACK 포기
  → 하지만 해시파워 높으면 재채굴 가능

V3+ (블록타임 단축):
  블록 폐기 = 50 JACK 포기 + 다른 채굴자에게 기회 넘김
  → 폐기의 기회비용 극대화
  → "차라리 꽝이어도 보상 챙기자" 심리 유도
```

### 설계 철학

```
"조작이 불가능"을 목표로 하지 않음
→ 현실적으로 완전 방지는 불가능

"조작이 비합리적"을 목표로 함
→ 경제적으로 손해가 되도록 설계
→ 합리적 행위자는 조작 안 함
→ 비합리적 행위자도 비용 부담

이것이 탈중앙화 시스템의 현실적 보안 모델
```
