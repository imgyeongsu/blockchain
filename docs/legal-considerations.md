# JackpotChain 법적 고려사항 및 안전 설계

## 개요

본 문서는 JackpotChain 프로젝트가 사행성 규제를 회피하기 위해 적용한 설계 원칙과 법적 고려사항을 정리합니다.

---

## 1. 한국 사행성 규제 개요

### 관련 법률
- **형법 제246조 (도박죄)**: 재물을 걸고 우연에 의해 재물의 득실을 결정하는 행위
- **게임산업진흥법**: 게임물의 사행성 규제
- **사행행위 등 규제법**: 사행행위영업의 규제

### 사행성 판단 기준 (3요소)
1. **우연성**: 결과가 우연에 의해 결정
2. **재산상 이익**: 금전적 가치가 있는 것을 획득/상실
3. **사행심 조장**: 일확천금 심리 자극

**3요소가 모두 충족되어야 사행성으로 판단됩니다.**

## 2. JackpotChain 안전 설계

### 2.1 토크노믹스 분리 설계

```
┌─────────────────────────────────────────────────────────────┐
│                    자산 이원화 구조                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   JACK (재화)                    POT (점수)                 │
│   ├─ 채굴로 획득                 ├─ 가챠 당첨으로만 획득     │
│   ├─ 송금 가능 ✓                 ├─ 송금 불가 ✗             │
│   ├─ 가챠 참여 비용              ├─ 순수 점수/랭킹 용도      │
│   └─ 교환 가치 있음              └─ 교환 가치 없음          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**핵심 포인트:**
- POT은 **거래 불가능**하므로 재산상 가치 없음
- 가챠 당첨으로 얻는 것은 POT(점수)뿐
- JACK은 채굴(노동)로 획득 → 우연성 없음

### 2.2 우연성 요소 분석

| 활동 | 우연성 | 재산상 이익 | 사행성 해당 |
|------|--------|-------------|-------------|
| JACK 채굴 | ✗ (노력 비례) | ✓ | **해당 없음** |
| 가챠 참여 | ✓ | ✗ (POT은 점수) | **해당 없음** |
| POT 랭킹 | ✗ | ✗ | **해당 없음** |

### 2.3 블록체인 특성과 법적 책임

```
중앙 서버 운영자 (기존 서비스)     vs     블록체인 (탈중앙화)
├─ 서비스 제공자 명확               ├─ 서비스 제공자 불명확
├─ 이용약관 존재                    ├─ 프로토콜만 존재
├─ 운영자 책임 발생                 ├─ 코드 작성자 ≠ 운영자
└─ 규제 대상 명확                   └─ 규제 대상 모호
```

**탈중앙화 특성:**
- 코드 공개 = 운영 아님
- 각 노드 운영자가 자발적 참여
- 중앙 통제 불가능 → 서비스 운영자 부재

## 3. 커뮤니티 이벤트 가이드라인

### 3.1 안전한 이벤트 설계

SSAFY 등 커뮤니티에서 이벤트 진행 시 권장 사항:

#### 권장 방식 (채굴 경쟁)
```
"100만 JACK 먼저 채굴한 사람에게 치킨 기프티콘 지급"
```
- ✅ 우연성 없음 (노력/시간 비례)
- ✅ 게임 대회와 동일한 구조
- ✅ 법적 리스크 최소

#### 주의 필요 방식 (가챠 기반)
```
"가챠로 POT 100점 달성 시 상품 지급"
```
- ⚠️ 우연성 존재
- ⚠️ 참여에 JACK 소모 (간접 비용)
- ⚠️ 상품 = 재산상 이익

### 3.2 이벤트 주최 시 안전장치

1. **참가비 무료**: JACK을 무료로 배포 후 시작
2. **상품 최소화**: 소액 상품 or 비금전적 보상
3. **교육 목적 명시**: 블록체인 학습 워크샵 형태
4. **1회성 한정**: 지속적 운영 아님을 명확히
5. **참여 제한**: 동의서 작성, 성인 한정

### 3.3 권장 이벤트 형태

```
┌─────────────────────────────────────────────────────────────┐
│              블록체인 학습 워크샵 (권장 형태)                 │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  1. 교육 세션 (1시간)                                        │
│     - 블록체인 기초 이론                                     │
│     - PoW/UTXO 개념 설명                                    │
│     - JackpotChain 아키텍처                                 │
│                                                             │
│  2. 실습 세션 (2시간)                                        │
│     - 노드 설치 및 실행                                      │
│     - 지갑 생성 및 채굴                                      │
│     - 트랜잭션 전송 실습                                     │
│                                                             │
│  3. 채굴 경쟁 (1시간)                                        │
│     - 목표 JACK 달성 경쟁                                    │
│     - 상위 3명 소정의 상품                                   │
│                                                             │
│  → 교육이 주목적, 경쟁은 부가 활동                           │
│  → 상품은 참여 감사 차원의 소액                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 5. POT 거래불가의 필수성

### 5.1 환금성 루프의 위험

POT이 거래 가능하면 완벽한 도박 구조가 형성됩니다:

```
┌─────────────────────────────────────────────────────────────┐
│                 POT 거래 가능 시 (위험)                      │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│   JACK 투입 → 가챠 → POT 당첨 → JACK 환전 → 다시 가챠      │
│       │                                   │                 │
│       └───────────── ♻️ 무한 루프 ─────────┘                │
│                                                             │
│   = 카지노의 칩 구매 → 도박 → 환전 구조와 동일              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 사행성 3요소 비교

| 요소 | POT 거래불가 (현재) | POT 거래가능 (가정) |
|------|---------------------|---------------------|
| 우연성 | ✓ 있음 | ✓ 있음 |
| 재산상 이익 | ✗ POT은 점수 | ✓ JACK 환전 가능 |
| 재산상 손실 | ✗ 점수만 획득 | ✓ 환전 차익/손실 |
| **판정** | **2/3 → 도박 아님** | **3/3 → 도박** |

### 5.3 실제 처벌 사례

```
바다이야기 (2006)
├─ 구조: 게임머니 → 게임 → 경품 → 현금 환전
├─ 결과: 운영자 구속, 사회적 파장
└─ 핵심: "환금 루트"가 있었음

웹보드게임 (포커/맞고)
├─ 구조: 현금 → 게임머니 → 게임 → 환전
├─ 결과: 게임사 제재, 환전상 구속
└─ 핵심: 게임사가 막아도 "환전상"만으로 위법

→ POT 거래 가능 = 환금성 = 위법 구조
```

### 5.4 결론

**POT 거래불가는 법적 방어의 핵심입니다. 절대 제거하면 안 됩니다.**

```

## 7. 탈중앙화와 통제권

### 7.1 신뢰와 가치의 역설

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│   개발자 권한 ↑↑↑              개발자 권한 ↓↓↓              │
│        │                            │                      │
│        ▼                            ▼                      │
│   "언제든 조작 가능"            "조작 불가능"                │
│        │                            │                      │
│        ▼                            ▼                      │
│   신뢰도 = 0                    신뢰도 = 높음                │
│        │                            │                      │
│        ▼                            ▼                      │
│   시장가치 = 0                  시장가치 = 있음              │
│        │                            │                      │
│        ▼                            ▼                      │
│   훔칠 것도 없음 ✓              탈중앙화 성공 ✓              │
│                                                             │
│   → 어느 쪽이든 "사기"가 성립 안 됨                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 7.2 통제 불가 시나리오

프로젝트가 성장하여 개발자 통제를 벗어난 경우:

```
시나리오 A: 버그 발견
├─ 개발자: "새 버전 나왔어요"
├─ 커뮤니티 동의 → 업데이트 → 해결
└─ 커뮤니티 거부 → 포크 분리 (개발자 책임 아님)

시나리오 B: 규제 당국 연락
├─ 당국: "이거 멈춰요"
├─ 개발자: "저도 못 멈춰요, 코드만 올렸어요"
└─ 전 세계 노드 통제 불가 → 사실상 불가능

시나리오 C: 거래소 상장
├─ JACK 가격 형성
├─ 개발자: "저는 관여 안 했어요"
└─ 커뮤니티 주도 → 개발자는 "개발자 중 1명"일 뿐
```

### 7.3 법적 방어 논리

```

## 9. 결론

### JackpotChain이 법적으로 안전한 이유

1. **POT 거래 불가**: 가챠 당첨 보상에 재산적 가치 없음 (핵심 방어선)
2. **JACK 채굴 기반**: 주요 획득 수단이 노동(채굴), 우연성 없음
3. **탈중앙화**: 서비스 운영자 부재, 개발자 통제 불가
4. **오픈소스**: 코드 공개 ≠ 서비스 운영, 표현의 자유
5. **교육 목적**: 블록체인 학습용 프로젝트로 명시

### 핵심 인사이트

```
┌─────────────────────────────────────────────────────────────┐
│                    자기 조절 메커니즘                        │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  개발자 권한 많음 → 신뢰 없음 → 가치 없음 → 피해 없음       │
│  개발자 권한 없음 → 신뢰 있음 → 탈중앙화 성공               │
│                                                             │
│  → 어느 쪽이든 "사기"가 성립 불가                           │
│  → 블록체인의 경제적 자기 조절 메커니즘                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 절대 하면 안 되는 것

1. ❌ POT 거래 기능 추가
2. ❌ POT ↔ JACK 교환 기능
3. ❌ ICO/토큰 판매
4. ❌ 수익률 약속/투자 권유
5. ❌ 공식 거래소 운영

### 주의사항

- 이 문서는 법률 자문이 아닙니다
- 실제 이벤트 진행 시 법률 전문가 상담 권장
- 각 국가/지역 법률에 따라 판단이 달라질 수 있음
- 프로젝트 성장 시 법률 검토 재실시 권장
